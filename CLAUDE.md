# RYSHelm

Окно «Сервер» семьи RYS для больших и публичных серверов: роли и права, наказания с лестницей, жалобы, журнал персонала, правила при входе, команды оператора. Замена модерации FTB Essentials (перемещения ушли в RYSMap, «Места»). modid `ryshelm`, пакет `works.repka.ryshelm`, NeoForge 1.21.1, ядро вшито через jarJar. Автор Дмитрий (MityaYS, RepkaWorks).

План и макеты: `../../_shared/_audit/essentials/PLAN.md` (разделы 2, 5, 6, 7, решения раздела 11), `img/08`–`14`. Контракты ядра: `../../_shared/_audit/essentials/core-api.md`. Вид и тон семьи: `../RYSCore/CLAUDE.md`, прочитать перед правками интерфейса.

## Устройство

* `logic`: чистая логика без игры, под JUnit. `Term` сроки, `Ladder` лестница наказаний, `Caps` потолки модератора, `RulesText` правила из `config/ryshelm/rules.md`.
* `data`: `HelmData` всё одним файлом `world/ryshelm/helm.json` (Gson, поле `v`), `HelmSettings` в `world/serverconfig/ryshelm-server.json`, `Journal` по месяцам `world/ryshelm/journal-ГГГГ-ММ.jsonl`.
* `server.Helm`: данные, настройки, правила, журнал, поставщик ролей (`Roles.provide`) и таблица прав (`Perms.policy`). Права проверяются на сервере в `Requests` и `Commands`, клиенту не верим.
* `server.Punish`: наказания. Бан ложится и в список игры `banned-players.json` со сроком (виден `/pardon`, переживает удаление мода).
* `server.Staff`: к игроку и позвать через `TravelApi` ядра, наблюдение, заморозка, инвентарь и сундук Края (`Peek`, «только смотреть»), корзина, команды оператора.
* `server.Chat`: заглушение (чат и команды сообщений), чат персонала, строки чата для жалоб. Слушатель стоит первым (`HIGHEST`): каналы RYSTeams тоже идут через `ServerChatEvent`.
* `server.Gate`: правила при входе и новичок. `server.Reports`: жалобы. `server.Sync` и `Views`: что уходит клиенту, окно подписывается на вкладку.
* `server.AdminMigration` и `AdminImport`: шаг переезда `admin` (порядок 60) из `world/ftbessentials`.
* Раздел 9 плана: `server.Kits` наборы (`world/ryshelm/kits.json`, пауза `logic.KitRule`), `logic.SpamGuard` антиспам, `server.Whitelist` белый список игры окном, `server.Afk` «отошёл» и выход по простою.
* `network.HelmNet`: два канала, необязательные (клиент без мода заходит на сервер с ним и наоборот).
* `client.ServerScreen`: окно рисуется целиком каждый кадр, нажимаемые места в `Kit.Hits`. `ReportsPane` вкладка «Жалобы» и форма жалобы, `RulesScreen` правила при входе, `ClientEntry` клавиша, кнопка панели, действия колеса.

## Правила проекта

* Узлы прав объявляются в `HelmPerms` и грузятся в конструкторе мода: позже объявленный узел не попадёт в PermissionAPI.
* Перемещения игроков только через `travel.TravelApi`, уведомления только `Notice.HELM`, ответ на вопрос только кнопками `accept`/`decline` ядра.
* Пока загружен FTB Essentials, корневые имена его команд не занимаем (`Commands.FTB_ROOTS`), шаг `admin` не идёт. Всегда доступны `/rys admin …`, `/rys rules`, `/report`, `/sc`.
* Код ядра, RYSMap, RYSClaims и RYSTeams отсюда не трогаем. Чего не хватает в контракте ядра, пишем блоком «Запрос к RYSCore».
* Каждое действие персонала ложится в журнал (`Helm.log`).
* Всё для публичных серверов (правила при входе, новичок, стартовый набор, антиспам, белый список, выход по простою) по умолчанию выключено: RepYS и большинство серверов на ней это серверы друзей (решение вопроса 5).

## Не сделано и почему

* «Исчезнуть» для персонала (`ryshelm:vanish` в кольце «Оператор»): нужен перехват отслеживания сущностей миксином, без проверки в игре не делаем.
* Свои роли сверх трёх: в `perm.Roles` ядра только оператор, модератор, игрок. Канал персонала в Tab: правка RYSTeams.
* Вето телепорта для новичка и не принявшего правила в окне карты, журнал мест RYSMap, «Пожаловаться» из меню игрока на карте: нужны контракты ядра (запрос в отчёте А1–А4).

## Проверка

```bash
gradlew test                               # JUnit: сроки, лестница, потолки, правила, журнал, шаг admin
gradlew runAutotest                        # окно и логика в новом мире, снимки run/screenshots/helm_08..14
gradlew runAutotest -Pautotest=migrate     # шаг admin на копии файлов FTB сервера RepYS
sh tools/duo.sh                            # сервер и два клиента: правила, жалоба, заморозка, мут, наблюдение
```

Тяжёлые запуски (автотест, duo) только когда не запущены сервер и игра автора и не идёт другой тяжёлый запуск. Непроверенное в игре записывать в `../../_shared/_audit/UNTESTED.md`.

Сборка требует соседний `../RYSCore` с выполненным `gradlew publish`.
